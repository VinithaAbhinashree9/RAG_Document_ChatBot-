# RAG Document Chatbot

A retrieval-augmented Q&A chatbot: upload documents, get a grounded, cited
answer to any question about them. No hallucinated pages, no invented
citations — the model can only cite chunks it was actually given.

- **Backend:** FastAPI, ChromaDB (vector store), sentence-transformers
  (embeddings), Groq (LLM)
- **Frontend:** React + TypeScript + Vite.

## Features

- Upload PDFs, Office docs, spreadsheets, presentations, markup, and plain
  text — see `GET /api/health` for the full supported-extension list
- Structure-aware chunking (paragraph → line → sentence → word) so citations
  stay accurate and sentences are never cut mid-way
- Query rewriting for follow-up questions ("what about *its* revenue?")
  using recent chat history
- Deterministic refusal when nothing relevant is retrieved — no LLM call, so
  no chance of an invented answer
- Per-document and multi-document chat modes
- Streaming responses (SSE) with citations delivered alongside the answer
- In-memory or ChromaDB vector store, swappable via config

## Prerequisites

- Python 3.11+
- Node.js 18+
- A free [Groq API key](https://console.groq.com/keys)

## Setup

### 1. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

Create `backend/.env`:

```env
GROQ_API_KEY=your_key_here
GROQ_MODEL=openai/gpt-oss-120b
```

> Uploads and indexing work without a key; chat and summarization need it.

Run the API:

```bash
uvicorn app.main:app --reload --port 8000
```

- Health check: http://localhost:8000/api/health
- Interactive docs: http://localhost:8000/docs

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Visit http://localhost:5173. Both terminals need to stay running (backend on
`8000`, frontend on `5173`) — Vite proxies `/api` to the backend in dev.

## Configuration

All tunables live in `backend/app/config.py` and are overridable via
`backend/.env`. Notable ones:

| Variable | Default | Purpose |
|---|---|---|
| `GROQ_API_KEY` | *(empty)* | Required for chat/summarization |
| `GROQ_MODEL` | `openai/gpt-oss-120b` | Chat completion model |
| `EMBEDDING_MODEL` | `sentence-transformers/all-MiniLM-L6-v2` | Local embedding model |
| `EMBEDDING_OFFLINE_FALLBACK` | `false` | Use a dependency-free hashing embedder instead (lower quality, no network needed) |
| `VECTOR_STORE` | `chroma` | `chroma` or `memory` |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1200` / `180` | Chunking granularity |
| `RETRIEVAL_TOP_K` | `6` | Chunks retrieved per query |
| `MAX_UPLOAD_MB` | `25` | Upload size limit |

## Building for production

```bash
cd frontend
npm run build      # outputs to frontend/dist
```

Serve `frontend/dist` from any static host, or point the backend at it, and
run the backend with a production ASGI server (e.g. `uvicorn` behind
`gunicorn`, or `uvicorn --workers N`).

## Security notes

- Never commit `backend/.env` — it holds your live Groq API key.
- `GROQ_API_KEY` is only ever reported as configured/not-configured via
  `/api/health`; the key itself is never returned by any endpoint.

## .gitignore

The repo's `.gitignore` keeps the following out of version control:

| Category | Paths | Why |
|---|---|---|
| Python artifacts | `__pycache__/`, `*.py[cod]` | Generated bytecode |
| Virtual environments | `venv/`, `venv311/`, `backend/venv/` | Local, machine-specific, huge |
| Secrets | `.env`, `.env.*` (but **not** `.env.example`) | Holds your live `GROQ_API_KEY` |
| Frontend build output | `frontend/node_modules/`, `frontend/dist/`, `frontend/.vite/`, `tsconfig.tsbuildinfo` | Reinstalled/rebuilt from `package.json` |
| IDE settings | `.vscode/`, `.idea/` | Personal editor config |
| Logs | `*.log` | Runtime noise |
| Local vector store / DB | `chroma/`, `chromadb/`, `*.db`, `backend/data/` | Regenerated from your uploaded documents |
| Uploaded documents | `uploads/`, `documents/`, `data/` | User content, not source code — and may be sensitive |
| OS files | `.DS_Store`, `Thumbs.db` | macOS/Windows filesystem clutter |

If you ever accidentally commit `.env` before this takes effect, removing it
in a later commit isn't enough — it stays in git history. Use
`git rm --cached backend/.env` plus a history rewrite (or just rotate the key,
which is the safer default regardless).

## Pushing to GitHub (Windows Command Prompt)

These steps work the same in `cmd.exe` or Git Bash — it's all plain `git`
commands, just typed at a different prompt.

1. **Rotate your Groq key first** if it's ever been in a `.env` you shared,
   uploaded, or committed anywhere. Get a fresh one at
   console.groq.com/keys and put it in your local `backend/.env` only.

2. **Open Command Prompt and go to the project folder:**
   ```cmd
   cd C:\Users\<you>\Downloads\rag-doc-chatbot-fixed
   ```

3. **Initialize git** (skip if already done):
   ```cmd
   git init
   ```

4. **Stage everything** — `.gitignore` keeps secrets and build output out
   automatically:
   ```cmd
   git add .
   ```

5. **Check what's staged** — confirm `.env` is NOT in the list:
   ```cmd
   git status
   ```

6. **Commit:**
   ```cmd
   git commit -m "Initial commit: RAG document chatbot"
   ```

7. **Confirm the commit exists:**
   ```cmd
   git log --oneline
   ```

8. **Rename the branch to `main`** (GitHub's default):
   ```cmd
   git branch -M main
   ```

9. **Create an empty repo on GitHub** (no README/gitignore — you already
   have both), then point your local repo at it:
   ```cmd
   git remote add origin https://github.com/<your-username>/<repo-name>.git
   ```
   If you'd already added a remote before and need to change it:
   ```cmd
   git remote set-url origin https://github.com/<your-username>/<repo-name>.git
   ```

10. **Push:**
    ```cmd
    git push -u origin main
    ```

11. **Verify on GitHub** that `backend/.env` did *not* upload — you should
    only see `backend/.env.example` there.

**If Command Prompt asks for a password and rejects it:** GitHub no longer
accepts your account password over HTTPS. Use a
[Personal Access Token](https://github.com/settings/tokens) as the password
instead, or install the [GitHub CLI](https://cli.github.com/) and run
`gh auth login` once, then push normally.
